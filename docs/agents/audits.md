# Audits

## Search and answer engines: `npm run audit:geo -- <url>`

`scripts/geo-audit.mjs` is the same file in all four public repos; only its `PROFILE` differs, and
`src/lib/geoAudit.test.ts` holds the shared check list. No browser: it reads the raw server HTML a
crawler gets, starting from `robots.txt` and the sitemap.

Shop-specific rules:

- **It never walks `/go/`**, which counts a click and forwards to a partner.
- **`Review` and `AggregateRating` are in `forbiddenTypes`.** There are no reviews; rating markup
  would be a lie and a manual-action risk.
- **Every product page shows a date.** `product.updatedAt` is the `Stand` line and the
  `dateModified`; the audit fails a `dateModified` without a visible `<time>`.

`/llms.txt` is generated (`src/lib/llmsTxt.ts` + `src/pages/llms.txt.ts`, `prerender = false`) and
names the shop's legal texts.

- **It states no price**, deliberately: it is rendered from a cached read and cached again
  downstream. It states the 24-hour rule instead.
- There is no `public/llms.txt` and must not be; a static asset shadows the route.

`public/og-default.png` is generated by `npm run og:default` and committed. There is no per-page OG
renderer: product images are partner assets that the Amazon PA-API forbids rehosting or editing.

Local limit: demo fixtures mark every product `editorialStatus: "none"`, so without a reachable API
the sitemap holds only the two front pages. Run the audit against the deployed site after a release.

## Accessibility: `MSYS_NO_PATHCONV=1 npm run audit:a11y -- <url> / /en/ /rechtliches/impressum`

axe-core in a real Chrome at **WCAG 2.2 AA**, the level `/rechtliches/barrierefreiheit` claims. CI
runs it after the tests against the **dev** server with a dead API and demo content; CI must never
read production content to decide whether a PR is mergeable.

- The dev server is a **daemon** (`astro dev stop`, `astro dev status`). A plain `npm run dev` may
  attach to an old instance and serve old markup.
- It can end up bound to `[::1]` only; prefer `localhost` over `127.0.0.1` here.

**A green run is not compliance.** Automated checks reach about a third of WCAG. Check by reading:

- Focus order follows reading order, and every stop shows a ring (`:focus-visible` is centralised
  in tds-shared; never `outline: none`).
- The skip link moves focus. It only does because `<main>` has `tabindex="-1"`.
- Error messages say how to fix the error and are associated with the field.
- Refusing consent is exactly as easy as granting it (same class on both decisions; tds-shared's
  `consent.test.tsx` checks the class, not later CSS overrides).
- Links make sense on their own.
- Decorative graphics (`.tds-wash`, `.tds-shape`, `.tds-brandbar`) carry `aria-hidden="true"`.

## Mobile: `MSYS_NO_PATHCONV=1 npm run audit:mobile -- <url> 390 / /produkt/<slug>`

In Git Bash, `MSYS_NO_PATHCONV=1` is required; otherwise every `/path` argument becomes a Windows
path. `scripts/mobile-audit.mjs` drives Chrome at a phone viewport and reports horizontal overflow
and tap targets under 24 CSS px.

- **Measure, don't look.** `body { overflow-x: hidden }` clamps `document.scrollWidth` to the
  viewport and clips overflow, so a screenshot of a broken layout looks correct. The audit lifts the
  clamp and checks each element's own rect.
- Confirm the tool still bites: append a 900 px-wide div and check the reported width moves.
- **Measure against realistic content.** `src/lib/demoContent.ts` has no prices or offers, so it only
  proves an empty card fits. Point `PUBLIC_API_URL` at a stub with long German titles and several
  offers per product.
- Links **inside a sentence** are exempt (as in WCAG 2.5.8); a link alone in its paragraph stays in
  scope.
